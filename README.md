# migrantsApp

Приложение для загрузки и обработки результатов тестирования знаний русского языка у мигрантов.

## Запуск готового приложения на Windows

На компьютере пользователя нужны Docker Desktop и Git. Node.js, npm и
PostgreSQL отдельно устанавливать не требуется.

- `Запустить приложение.cmd` — запускает Docker Desktop при необходимости,
  поднимает базу, API и сайт, затем открывает браузер.
- `Остановить приложение.cmd` — останавливает контейнеры без удаления данных.
- `Обновить приложение.cmd` — создаёт резервную копию базы, выполняет безопасный
  `git pull --ff-only`, пересобирает контейнеры и открывает новую версию.
- `Восстановить базу.cmd` — восстанавливает `migrants_db.dump`, лежащий рядом с
  файлом. Дамп также можно перетащить мышкой на этот `.cmd`.

Адрес приложения: <http://localhost:8080>.

Ручной запуск из корня проекта:

```powershell
docker compose up -d
```

Ручная остановка:

```powershell
docker compose stop
```

Резервные копии, Docker volume с PostgreSQL и `.env` в Git не добавляются.

## Запуск для разработки

Требования: Node.js 22+, npm, Docker Desktop и Python 3.10+ для генерации отчётов.

```powershell
docker compose up -d postgres
npm ci --prefix server
npm ci --prefix client
python -m pip install -r server/reports/requirements.txt
if (-not (Test-Path server/.env)) { Copy-Item server/.env.example server/.env }
```

В двух отдельных терминалах из корня проекта:

```powershell
npm run dev --prefix server
```

```powershell
npm run dev --prefix client
```

Сайт: <http://localhost:5173>, API и Swagger: <http://localhost:3000/docs>.
Vite перенаправляет `/api` на локальный сервер. Для остановки нажмите `Ctrl+C`
в обоих терминалах, затем выполните `docker compose stop postgres`.

## Отчёты

- **Статистико-аналитическая справка** — Word DOCX за период; сохраняет разделы,
  тексты и таблицы исходной Python-программы. Контрольные даты нужны только для Excel.
- **Статистика ИГ** — Excel с отдельными листами на выбранные даты и накопительными
  показателями внутри периода. Как в исходной программе, общие листы в конце книги
  строятся на последнюю выбранную контрольную дату.
- **Сводная** — Excel с первым листом в формате исходной таблицы (24 столбца), одна
  строка на тестирование. По умолчанию выбран весь диапазон дат базы. При включённом
  пересчёте скачивается ZIP с исходной и пересчитанной таблицами.

Период учитывается включительно. При пересчёте остаются только завершённые попытки
(«Зачет» и «Незачет»); кратность назначается по ID участника и дате, при одинаковой
дате — по ID тестирования. Сохранённые значения в БД не меняются. Подсчёт людей берёт
последнюю завершённую попытку каждого участника в периоде; человекотесты учитывают все
завершённые попытки. Неявки сохраняются в исходной сводной.

Оба старых столбца ID в сводной содержат текущий `participants.id`: отдельный ID
для статистики в нормализованной схеме не хранится. Территория берётся из направляющей
школы. Название ППТ и название школы заполняются из справочников; апелляция собирается
из даты и двух признаков. Дополнительные листы старого Excel не воспроизводятся.

Express читает БД и запускает `server/reports/generate.py` как дочерний процесс.
Отдельный Python-сервер не нужен. Если Python недоступен как `python`, задайте
`REPORT_PYTHON` в `server/.env` — полный путь к интерпретатору с установленными
зависимостями. Docker-образ сервера уже включает интерпретатор и библиотеки.

Проверка отчётов на заполненной локальной БД (только чтение):

```powershell
npm run test:reports --prefix server
```

Тест скачивает DOCX/XLSX/ZIP через HTTP и сверяет содержимое с независимыми SQL-запросами.
Контрольные файлы сохраняются в игнорируемой Git папке `server/.report-checks-*`.
Подробности реализации и проверки: [docs/reports.md](docs/reports.md).

## База данных

При первом создании Docker volume PostgreSQL автоматически выполняет:

1. `database/schema.sql` — создание таблиц.
2. `database/reference_data.sql` — первоначальное заполнение справочников.

При последующих запусках контейнера эти скрипты повторно не выполняются, поэтому изменения справочников, сделанные через приложение, сохраняются.

## Структура

- `client/` — React/Vite-клиент.
- `server/` — Express/TypeScript API.
- `database/` — SQL-схема и скрипт отката.
