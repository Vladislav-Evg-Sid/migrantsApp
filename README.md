# migrantsApp

Локальное приложение для учёта участников и результатов тестирования по русскому языку.
React/Vite + Express/TypeScript + PostgreSQL. Отчёты Word и Excel формирует Python-генератор,
который запускается из Express; отдельного Python-сервера нет.

## Развёртывание на Windows

### Зависимости

На компьютере сотрудницы нужны:

- [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с WSL 2 и Linux containers.
- [Git for Windows](https://git-scm.com/install/windows).
- Браузер и программа для открытия DOCX/XLSX.

Node.js, Python и PostgreSQL отдельно ставить не нужно — всё есть в Docker-образах.
Интернет нужен для установки, первой сборки и обновлений. Обычная работа выполняется локально.
Docker и приложение настраивай под учётной записью сотрудницы.

Если WSL ещё не установлен, в PowerShell от администратора:

```powershell
wsl --install --no-distribution
```

После перезагрузки:

```powershell
wsl --update
wsl --set-default-version 2
```

Установи и запусти Docker Desktop, затем проверь:

```powershell
git --version
docker version
docker compose version
```

У Docker должны отвечать и Client, и Server. Требования к Windows и виртуализации —
на странице установки Docker выше.

### Проект и первый запуск

Клонируй в постоянную локальную папку. Сейчас изменения находятся в `feature/data_upload`:

```powershell
git clone --branch feature/data_upload https://github.com/Vladislav-Evg-Sid/migrantsApp.git
cd migrantsApp
& ".\Первый запуск.cmd"
```

Скрипт соберёт образы, запустит контейнеры, проверит доступность сайта и API, откроет браузер.
Адрес приложения: <http://localhost:8080>. Для запуска через Docker файл `server/.env` не нужен.

То же вручную, без открытия браузера:

```powershell
docker compose up -d --build
```

### Перенос текущей базы

Данные в Git не хранятся. При первом запуске создаются только схема и начальные справочники.
Для переноса существующего учёта используй дамп всей БД.

На исходном компьютере из корня проекта:

```powershell
& ".\Создать резервную копию.cmd"
```

Возьми новый `.dump` из `database\backups`. На компьютере сотрудницы положи его в корень
проекта под именем `migrants_db.dump`, затем выполни:

```powershell
& ".\Восстановить базу.cmd"
& ".\Запустить приложение.cmd"
```

Восстановление запрашивает подтверждение (`Y`), делает страховочную копию, останавливает
приложение и заменяет БД одной транзакцией. Можно также перетащить любой `.dump`
на `Восстановить базу.cmd`, не переименовывая файл.

Импорт Excel через интерфейс — другой сценарий: он заменяет участников и экзамены,
но использует существующие справочники школ и ППТ. Для переноса между компьютерами
предпочтительнее дамп.

### Проверка перед передачей

- Сверь участников и экзамены с исходной базой, открой несколько карточек.
- Сформируй три вида отчётов и проверь скачанные файлы.
- Проверь создание копии и сохранность данных после остановки/повторного запуска.
- Сделай сотруднице ярлыки на запуск, остановку и резервное копирование.
  Памятка для неё: [Как работать с приложением.txt](Как%20работать%20с%20приложением.txt).

## Запуск и обслуживание

Все `.cmd` находятся в корне проекта:

| Файл | Действие |
| --- | --- |
| `Первый запуск.cmd` | Сборка и запуск после установки |
| `Запустить приложение.cmd` | Запуск приложения и браузера |
| `Остановить приложение.cmd` | Остановка без удаления данных |
| `Создать резервную копию.cmd` | Дамп в `database\backups` с датой и временем |
| `Обновить приложение.cmd` | Бэкап, `git pull --ff-only` текущей ветки, сборка и запуск |
| `Восстановить базу.cmd` | Замена базы из выбранного дампа со страховочной копией |

Обновляй после завершения работы сотрудницы. Для скрипта обновления нужна чистая рабочая
папка и доступ к GitHub, Docker Hub, npm и PyPI. Изменения схемы требуют отдельной миграции:
`database/schema.sql` и `database/reference_data.sql` выполняются только при создании volume.

База хранится в volume `migrantsapp_postgres_data`. Копирование папки проекта не переносит БД.
Не удаляй volume через `docker compose down -v` или сброс Docker Desktop. Резервные копии
храните также отдельно от рабочего компьютера.

Диагностика из корня проекта:

```powershell
docker compose ps
docker compose logs --tail 100
```

Используемые порты: `8080` — сайт, `55432` — PostgreSQL; оба доступны только локально.

## Разработка

Нужны Node.js 22+, npm, Docker Desktop и Python 3.10+.

```powershell
docker compose up -d postgres
npm ci --prefix server
npm ci --prefix client
python -m pip install -r server/reports/requirements.txt
if (-not (Test-Path server/.env)) { Copy-Item server/.env.example server/.env }
```

В двух терминалах из корня:

```powershell
npm run dev --prefix server
```

```powershell
npm run dev --prefix client
```

Клиент: <http://localhost:5173>, Swagger: <http://localhost:3000/docs>.
Vite проксирует `/api` на Express. Если Python установлен под другим именем или в отдельном
окружении, задай путь к интерпретатору в `REPORT_PYTHON` в `server/.env`.

Проверка отчётов на заполненной локальной БД, без изменения её данных:

```powershell
npm run test:reports --prefix server
```

## Структура

- `client/` — интерфейс React/Vite.
- `server/src/` — Express API и работа с БД.
- `server/reports/` — генерация DOCX/XLSX.
- `server/imports/` — чтение и проверка сводной Excel.
- `database/` — схема и начальные справочники.
- `scripts/` — запуск, обновление, резервное копирование и восстановление.
